# VPNonly

Per-app WireGuard routing for macOS. VPNonly keeps the Mac on its normal
connection and moves only the apps you choose into a VPN tunnel.

**[Website](https://vpnonly.app/)** · **[Install guide](https://vpnonly.app/install.html)** · **[How it works](https://vpnonly.app/how-it-works.html)** · **[VPNonly for Mac — $19](https://dodo.pe/vpnonly-github)**

## Privileged source

Starting with VPNonly 1.9.8, each app release publishes the exact source for
the root-owned engine in [`app-engine/`](app-engine/). Its checksum manifest is
generated by the same release command that builds the app and update ZIP.

That engine:

- asks macOS for a free `utunN` instead of claiming a fixed interface;
- records the exact root process, interface, address and socket it owns;
- changes only VPNonly's dedicated PF anchor during normal operation;
- blocks selected app groups when their owned tunnel is unavailable;
- tears down only a tunnel proven to belong to VPNonly.

The menu bar application source is maintained separately. The code in
`app-engine/` is the complete privileged boundary: it is the part installed as
root and the part covered by the administrator approval.

## Historical CLI — do not install

The root-level shell and C files are the original prototype preserved for
historical reference. They hardcode `utun9`, replace PF's main ruleset and do
not implement the ownership and migration checks in the current engine.

They are not a supported installation method on current macOS. Do not run
their old setup commands. Use the app and inspect [`app-engine/`](app-engine/)
for the maintained privileged implementation.

## Current product limits

- Apple Silicon and macOS 13 or later.
- Safari and other WebKit apps cannot be routed reliably because their network
  processes are managed separately by macOS.
- App connections use the tunnel, but DNS queries still use the Mac's system
  resolver.
- IPv6 is blocked for selected apps rather than tunneled.
- Keep a provider's whole-Mac VPN connection disconnected if you want
  unselected apps to remain on the normal connection.
- The app is not Developer ID signed yet, so first launch requires the steps in
  the [install guide](https://vpnonly.app/install.html).

## Uninstalling

Use **Uninstall VPNonly** inside the app. If the app was already deleted, use
the audited current
[`vpnonly-clean-sweep.sh`](app-engine/vpnonly-clean-sweep.sh) from the
`app-engine` snapshot; do not use the historical root-level teardown scripts.
