Built on an open-source engine

The split-tunneling core is ~300 lines of auditable shell + C, MIT-licensed on GitHub. It uses macOS's built-in PF firewall and userspace WireGuard — no kernel extensions. A kill switch blocks a tunneled app's traffic if the VPN drops, instead of leaking it to your ISP. You can read every line that ever runs with elevated privileges.

FAQ

How does it work?

A userspace WireGuard tunnel comes up with no default route, so nothing uses it by default. macOS's built-in PF firewall steers traffic from your chosen apps into the tunnel. The engine is open source — inspect every privileged line on GitHub.

Which VPN providers work?

NordVPN works out of the box (paste an access token from your Nord account, once). Any provider that gives you a WireGuard config also works: Mullvad, Proton, IVPN, or your own server.

What happens if the VPN drops?

A kill switch blocks the tunneled apps' traffic entirely. It never silently falls back to your normal connection.

Why does it need my password at setup?

Creating a network interface and firewall rules requires admin rights on macOS — there's no legitimate way around that. VPNonly asks exactly once, installs a root-owned engine you can audit on GitHub, and never prompts again.

Known limitations?

v1 is Apple Silicon (M-series) only. DNS queries for tunneled apps currently use the system resolver — connections themselves are tunneled; a full DNS fix is on the roadmap. Apps need to be relaunched via the toggle to enter or leave the tunnel (VPNonly does this for you).
