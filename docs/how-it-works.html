How it works

Most VPN apps take over your whole machine. VPNonly inverts that: your Mac never joins the VPN — individual apps do.

The inversion

When a normal VPN app connects, it replaces your Mac's default network route. Every packet from every app — video calls, backups, banking — detours through a server in another country, whether it benefits or not.

VPNonly brings up a WireGuard tunnel with no default route at all. The tunnel exists, but nothing uses it. Then, for exactly the apps you choose, traffic is steered into it. Your Mac's own connection is never modified — which is why the worst possible failure is "one app is offline," and never "my internet broke."

The mechanism

  1. A userspace WireGuard interface (wireguard-go) connects to your VPN provider's server. No kernel extensions — it's an ordinary tunnel interface, visible in ifconfig.
  2. macOS's built-in PF firewall steers traffic into it. PF can't match packets by app, but it can match by unix group — so VPNonly runs your chosen apps under a dedicated group, vpnonly, and two rules do the rest: 
    pass out quick route-to (utun9 10.5.0.2) inet proto { tcp udp } \
    from any to any group vpnonly keep state
block return out proto { tcp udp } from any to any group vpnonly
    The first rule routes the group into the tunnel. The second is the kill switch: if the tunnel is down, that traffic is refused — never silently leaked to your ISP.
  3. A 30-line launcher starts your app under that group and immediately drops privileges. Every helper process the app spawns inherits the group, so multi-process apps (Chromium-based ones included) are covered.

Why the one-time password prompt

Creating network interfaces and firewall rules requires admin rights on macOS — for every app, always. VPNonly asks once: it installs a small engine, owned by root and writable by no one, plus a narrowly-scoped rule that permits only those exact scripts to run privileged. The scripts refuse to operate as root for launching apps, and the whole chain is short enough to read in five minutes.

Open source where it matters

Everything that ever runs with elevated privileges — the tunnel scripts, the firewall rules, the launcher — is the open-source engine, MIT-licensed on GitHub. The paid app is a native menu bar interface on top of that engine. You're never asked to trust an opaque binary with root.

Providers

NordVPN works out of the box: paste an access token once and VPNonly fetches your WireGuard credentials directly from Nord's API. The Nord app itself stays closed — VPNonly speaks to Nord's servers, not its software.

Any WireGuard provider works too: Mullvad, Proton, IVPN, or a server you run yourself. If you can get a WireGuard key, VPNonly can tunnel through it.

Honest limitations

  • Apps must relaunch to enter or leave the tunnel — VPNonly does this for you, with a warning first. (Removing even that requires Apple's Network Extension framework; it's on the roadmap.)
  • DNS queries for tunneled apps currently resolve via the system resolver. Connections themselves are fully tunneled; a scoped-DNS fix is planned.
  • Apple Silicon only for now. IPv6 for tunneled apps is blocked rather than routed — no leaks, but no v6.
