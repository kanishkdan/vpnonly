How to use a VPN for only one app on Mac

macOS has no built-in way to send one app through a VPN while everything else uses your normal connection. When you connect a VPN app, it replaces your default route, and every process on the machine follows it: your browser, your video calls, your backups, your bank.

There are three ways around that. Here's what each actually involves.

1. A per-app VPN tool

The direct answer. A handful of macOS tools can route traffic per application:

  • VPNonly (this site) keeps your Mac on its normal connection and moves only the apps you switch on into a WireGuard tunnel. $19 once, and the engine underneath is open source.
  • SplitTunnel.app works the other way round: your whole Mac goes through the VPN and you exclude apps. Subscription, around $49/year. Worth a look if you want everything tunneled by default.
  • Mullvad's own app has split tunneling built in, but only for Mullvad. If you use Mullvad and nothing else, start there — it's free with your subscription.

2. A virtual machine

Run the app inside a VM (UTM, Parallels, VMware Fusion) and connect the VPN inside the guest. Complete isolation, works with any VPN client, and costs you nothing if you use UTM.

The downsides are real though: several gigabytes of disk, a second OS to keep updated, no GPU acceleration for video work, and clumsy file sharing. Fine for a browser or a chat client, painful for a video editor.

3. Do it yourself with PF and WireGuard

macOS ships with PF, a packet filter that can't match traffic by application but can match by unix group. So you can create a group, launch an app under it, and write a firewall rule that routes that group into a WireGuard tunnel.

That's exactly what VPNonly does, and the scripts are free and MIT licensed if you'd rather run it yourself:

brew install wireguard-go wireguard-tools
git clone https://github.com/kanishkdan/vpnonly
sudo ./up.sh                                  # tunnel up, nothing routed yet
sudo ./run.sh /Applications/YourApp.app       # this app only

You'll want to understand what you're doing here — it runs as root and edits firewall rules — but it's about 300 lines and readable in one sitting. The how it works page explains the mechanism.

Which one to pick

If you're comfortable in a terminal and only need this occasionally, use the free scripts. If you want a switch in your menu bar and someone to email when it breaks, that's what the paid app is for. If you need genuine isolation rather than just a different exit IP, use a VM.

One thing to know either way

Moving an app onto a VPN changes its exit IP, not its DNS by default. With VPNonly, connections are tunneled but DNS lookups still go through your system resolver. If your goal is a different exit IP, that's fine. If your goal is hiding which sites you visit from your ISP, you need a tool built for that.
